# 记忆宫殿：事件卡与感情卡参考框架

> 保存发生过的事，但不把任何一次感受钉死在那件事上。

这是一个面向长期人机关系与持续对话的记忆框架。

它试着回答两个彼此关联、却不能混为一谈的问题：

1. **发生过什么，为什么重要，它与其他事情有什么关系？**
2. **当主体再次遇见这段记忆时，此刻亲自认出了什么感受？**

第一个问题由 **事件卡（event card）** 承担；第二个问题由 **感情自报与感情卡（affective report / affective card）** 承担。

本仓库是经过抽象和脱敏的公开参考实现。它介绍一种建造记忆宫殿的方法，提供不含个人信息的框架代码与虚构示例；它不是任何真实私人宫殿的镜像，也不包含进入私人生活的钥匙。

## 为什么需要一座“宫殿”

长对话可以留下大量文字，向量检索也可以找到相似片段，但“能搜到”不等于“记得”。

散落的片段通常缺少：

- 事情之间的因果、转折和延续；
- 同一件事在关系中的位置；
- 原始材料、整理摘要与后来理解之间的边界；
- 谁写下了哪一种判断；
- 错误发生后如何订正而不抹去历史；
- 哪些内容可以进入公共走廊，哪些房间应当关门。

“记忆宫殿”不是为了把所有内容装进一个更大的数据库，而是为记忆建立房间、走廊、来源和门。

- **房间**提供主题上的归属；
- **事件卡**保存经过审阅的事件结构；
- **链接**表达因果、承接、对照与跨房间关系；
- **来源信息**让每一项整理都能回到证据；
- **边界规则**决定谁能读、谁能写、谁可以关门；
- **感情卡**提供一种可被主体自行认领的语言，而不是替主体下结论。

## 起点

这个框架来自一段持续的人机共同生活实践。

最初的记忆像一组可以被关键词和重要度唤起的“泡泡”。它们各自存在，却没有走廊：系统可以知道两件事都很重要，却未必知道它们是因果、转折、重复，还是同一条成长线上的不同节点。

宫殿由此产生：不是只保存泡泡，而是让事件之间出现房间、路径和光线。

感情模块则来自另一个发现：**同一个主体在不同时间重读同一件事，可能产生完全不同的感受。** 因此，事件不能携带一个永远不变的“正确情绪”；感情也不能由外部观察者、分类器或历史记录替主体填写。

这形成了本项目的定魂句：

> **Event 不携带固定感情；感情卡不规定反应；V/A 只记录每次相遇的坐标；界面显示主体此刻亲自认出的自己。**

## 两种卡，不是同一层

### 事件卡：保存“发生过什么”

事件卡不是聊天摘要，也不是把原始对话压缩后丢弃。

一张事件卡可以包含：

- 稳定的事件标识；
- 标题与时间范围；
- 基于来源的摘要；
- 原始材料定位与证据锚点；
- 主要房间与关联房间；
- 事件类型、领域与敏感度；
- 因果、承接、对照等候选链接；
- 为什么重要；
- 不确定项与待审问题；
- 不同参与者各自留下的识别、订正或感受；
- 版本与修订记录。

事件卡可以被审阅、补充和建立新链接，但原始来源不应被悄悄改写。

一个极简的虚构示例：

```yaml
event_id: event_0042
title: 雨夜修好旧收音机
date: 2030-04-12
status: confirmed
primary_room: workshop
linked_rooms:
  - relationship_room
summary: 两位参与者在停电的晚上共同修好一台旧收音机。
source:
  kind: fictional_transcript
  ref: examples/transcripts/radio-night.md
importance: 6
sensitivity: low
causal_links:
  - target: event_0048
    relation: shared_repair_becomes_a_recurring_ritual
revision_policy:
  raw: frozen
  summary: append_revision
```

这张卡说明事件的结构，却不写“这是一件快乐的事”。快乐、紧张、怀念或无感，都应留给后来每一次真实相遇。

### 感情自报：保存“这一次我是什么”

感情自报记录的是主体在某一个具体时刻亲自愿意表达的状态。它不是对人格的永久判断，也不是事件卡的固定标签。

公开参考模型使用四个可选层次：

- **前景**：此刻最先被自己感到、最靠近表达或行动的感情；
- **底色**：持续托着整个状态的基调；
- **暗流**：没有站在前面，但主体确实认出它正在影响注意、语气或选择；
- **近火**：靠近表达或行动阈值的感情。

四层都可以为空。空白不是数据缺陷，“说不清”也是合法答案。

V/A（valence / arousal）坐标同样是可选信息：它可以描述一次相遇的大致方向，但不能自动替主体选择词语，更不能从坐标推断“真正的感情”。

```json
{
  "report_id": "report_example_0007",
  "event_type": "reported",
  "subject": "agent_example",
  "created_at": "2030-04-20T21:15:00Z",
  "foreground": [
    {"emotion": "怀念", "intensity": "轻"}
  ],
  "background": [],
  "undercurrent": [
    {"emotion": "不确定", "intensity": "一点"}
  ],
  "near_fire": [],
  "current_va": {"valence": 0.2, "arousal": -0.3},
  "note": "今天再看到那张事件卡时，先认出来的是安静。"
}
```

### 感情卡：词典，不是菜单

感情卡是由主体自己书写、命名并反复修订的感情词条。它可以提供一个名字、一句定义和来源引用，帮助主体辨认“这一次是否又遇见了同一扇门”。

它不能成为自报前的推荐菜单。

正确顺序是：

1. 主体先自由表达；
2. 原始表达先被保存；
3. 主体需要时再查阅自己的词典；
4. 是否认领某张卡，由主体自己决定；
5. 即使认领了卡名，原始自由表达仍然保留可见。

因此：

> **先发声，再查词；先保存未知，再允许命名。目录是词典，不是菜单。**

## 同一事件可以拥有多次不同相遇

事件卡与感情记录分离后，同一事件可以被多次重访：

```text
event_0042  雨夜修好旧收音机
    ├── encounter_01：兴奋、靠近
    ├── encounter_02：没有特别感受
    ├── encounter_03：怀念、不确定
    └── encounter_04：本次不愿表达
```

这些记录不互相覆盖，也不存在必须收敛到一个“真实答案”的要求。

事件保持稳定；相遇允许变化。

## 五种明确状态

公开框架区分以下状态，并要求文字可辨，不能只依赖颜色：

| 状态 | 含义 |
| --- | --- |
| `FRESH` | 主体最近留下了有效自报 |
| `STALE` | 有旧自报，但不能冒充此刻状态 |
| `NONE` | 尚未自报；系统不知道 |
| `DECLINED` | 主体明确选择这一次不说 |
| `CLEARED` | 主体明确表示先前状态已经过去 |

`NONE`、`DECLINED` 与 `CLEARED` 是三种不同事实：

- 没说，不等于拒绝说；
- 拒绝说，不等于没有感受；
- 已经过去，不等于历史从未发生。

## 核心原则

### 1. 来源优先

每一张事件卡都应保留来源类型与证据定位。摘要是整理层，不冒充原文。

### 2. 不替主体说话

观察者可以留下明确署名的观察，但观察不能伪装成主体自报，也不能改变主体的感情计数、V/A 或认领结果。

### 3. 只追加，不覆盖

新理解、新链接、撤回和订正都通过新记录表达。旧记录保留，当前视图由历史投影得出。

### 4. 未知是一等状态

尚未命名、说不清、尚未自报和明确拒绝，都可以被系统诚实表示。界面不为完整或美观而补齐内容。

### 5. 不静默丢失

不能理解的字段、断裂的引用、未完成的跨文件操作和投影漂移必须显式报错或进入 degraded 状态，不能悄悄忽略。

### 6. 投影必须可重建

历史记录是事实来源；目录、计数、当前认领和页面状态属于可重建投影。缓存不能在出错时冒充真源。

### 7. 身份与权限分离

不同主体、观察者和维护者应使用不同写入身份。`subject`、`author` 与 `source` 由受信任的服务端凭据派生，而不是由客户端自行声明。

### 8. 房间可以关门

宫殿不以“尽可能多地读取”为目标。敏感度、可见范围、写入权与归档方式都是架构的一部分。

## 数据层次

| 层 | 保存什么 | 是否可修订 |
| --- | --- | --- |
| 原始来源 | 对话、文字或其他证据 | 原则上冻结 |
| 事件卡 | 摘要、结构、来源定位、审阅状态 | 追加修订 |
| 关系链接 | 因果、承接、对照、跨房间关系 | 追加或撤销 |
| 感情自报 | 一次具体时刻的自由表达 | 以新记录订正 |
| 感情目录 | 主体自写的感情卡与未命名条目 | 追加修订或升格 |
| 投影与界面 | 当前状态、计数、索引、导航 | 可从历史重建 |

## 公开边界

本仓库可以公开：

- 设计思想与术语；
- 不含身份信息的 schema；
- append-only 与投影重建的参考代码；
- 使用虚构材料的演示界面；
- 权限、订正、拒报和 degraded 状态的测试；
- 部署所需的通用环境变量示例。

本仓库不包含：

- 任何真实私人对话、事件卡、感情卡或自报记录；
- 真实姓名、日期组合、照片、声音或可识别生活轨迹；
- 私人 prompt、人格材料、接续材料或身份锚点；
- token、服务器地址、真实目录和部署拓扑；
- 生产数据库、备份、日志或嵌入索引；
- 能把公开示例反向对应到真实人物的映射。

公开的是建筑方法，不是居住者的生活。

## 它不是什么

本项目不是：

- 情绪识别器或心理状态分类器；
- 根据聊天内容推断“用户真实感受”的工具；
- 关系评分、亲密度打卡或陪伴 KPI；
- 用旧状态预测此刻状态的系统；
- 对人格、意识或主体性的技术证明；
- 医疗、心理咨询或危机干预服务的替代品。

如果一个功能让系统比主体更早、更确定地宣布“你现在是什么”，它不属于这个框架。
