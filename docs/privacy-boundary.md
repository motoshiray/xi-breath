# 隐私与公开边界

> 公开的是建筑方法，不是居住者的生活。

## 可以公开

- 设计理念、术语和信息架构；
- 空白 Schema、配置模板与接口约定；
- 使用完全虚构人物和事件的样例；
- append-only、订正、撤回和投影重建的方法；
- 不包含私人入口的只读界面；
- 无障碍、权限边界与错误状态测试。

## 不应公开

- 真实对话、事件卡、感情自报、Memo 和时间线；
- 真实姓名、日期组合、位置、健康信息和生活轨迹；
- 照片、声音、头像、衣橱素材及未授权图像；
- 私人 prompt、人格材料、接续文件和身份锚点；
- Token、环境变量、服务器地址、目录与部署拓扑；
- 数据库、备份、日志、嵌入索引和真实 `report_id`；
- 能把虚构样例反向对应到真实人物的映射。

## “删掉姓名”不等于脱敏

罕见经历、精确日期、独特措辞和事件组合仍可能构成身份指纹。公开样例应重新虚构，而不是把真实记录换名后发布。

## 发布前检查

1. 在干净目录中组装公开包，不直接复制生产目录。
2. 搜索 `.env`、Token、IP、绝对路径、邮箱、手机号和真实姓名。
3. 检查 Git 历史，而不只检查当前文件。
4. 确认每一张图片和每一段文字都有公开授权。
5. 用新的虚构时间线测试示例能否独立运行。
6. 让至少一位未参与开发的人进行隐私复核。

## 居住者的权利

任何实现都应允许居住者知道系统保存了什么、导出自己的内容、限制读取范围、停止继续写入，并通过追加记录表达撤回或订正。技术上的可保存不等于关系中的可公开。
